# このアプリのスマホ対応の保証

スマホは縦持ちだけを保証する。下限は幅 320px の 1 つで、360px と 390px は見た目の確認の幅にする。
[解像度](resolution.md)と[レスポンシブ対応](responsive.md)の推奨を、このアプリに当てはめた文書で、原文にはない。
決定の経緯は [Issue #718](https://github.com/yokozi-jp/agent-software-factory/issues/718) の解決コメントにある。

## 保証する範囲

| 項目           | 内容                                                                                                                                        |
| :------------- | :------------------------------------------------------------------------------------------------------------------------------------------ |
| 対象の端末     | スマホの縦持ち。横持ちとタブレットは「操作不能にならない」まで。見た目は保証しない                                                          |
| 下限の幅       | 320 CSS px。横スクロールなしで内容と機能が使える ([WCAG 2.2 SC 1.4.10 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)、AA) |
| 確認の幅       | 360px (Android の多数派) と 390px (iPhone の多数派)。多数派の数字はまとめ記事のもので、一次の統計ではない                                   |
| 対象の画面     | ログイン、トップ、メニュー (ドロワー)、ユーザーメニュー (テーマの 3 択とログアウト)、403/404                                                |
| 切り替えの境目 | `md` (768px) の 1 か所。`packages/ui` の `use-mobile.ts` と CSS の `md:` が同じ値を見る。新しい境目は足さない                               |
| 保証の中身     | 文字が切れない、横スクロールが出ない、指で押せる                                                                                            |

## 押せる大きさ

- 24×24 CSS px 未満は CI で止める。axe の `target-size` (WCAG 2.2 SC 2.5.8、AA) を `apps/web/.storybook/preview.ts` の `a11y.options.runOnly` で有効にしている。`target-size` は `wcag22aa` のタグだけに付く。`runOnly` は書いたタグの規則だけを動かすので、`wcag2a`、`wcag2aa`、`wcag21a`、`wcag21aa`、`best-practice` も並べる。`wcag22aa` だけを書くと、既存の規則が外れる。
- `Button` の `default`、`lg`、`icon`、`icon-lg` と、`SidebarMenuButton` の `default` は、`md` 未満で 44×44 CSS px 以上にする (WCAG 2.2 SC 2.5.5、AAA の値。アプリ全体で AAA を採るわけではない)。モバイルファースト (Tailwind の公式の基本) で、部品の `cva` に `h-11 md:h-8` の形で持つ。呼び出し側に `max-md:` を書かない。`SidebarTrigger` は `size="icon"` を使う。
- `xs`、`sm`、`icon-xs`、`icon-sm` は、PC 向けの小さい寸法で、スマホでも小さいままになる。密な表など、小さいことを選ぶ場所だけで使い、スマホの主な操作 (ログインのボタン、メニューを開くボタン、メニューの項目、ユーザーメニューの項目) には使わない。
- 切り替えの条件は画面の幅 (`md`) にする。入力装置 (`pointer-coarse:`) の方が「指で触るか」を正確に表すが、story の環境は `pointer: fine` で、`contextOptions` の `hasTouch: true` を全 story に効かせる Vitest のプロジェクトを足す必要がある。縦持ちのスマホだけを保証する間は、幅で結果は同じで、サイドバーの切り替え (`use-mobile.ts`) とも条件がそろう。横持ちやタブレットを保証に含めるときに、`pointer-coarse:` へ移す。
- Oxlint の `jsx-a11y` は、描画後の大きさを見られないので、この検査には使えない。

## 検査

| 層    | 内容                                                                                                                                                                                       | 流す場所                 |
| :---- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------- |
| story | `apps/web/src/app.stories.tsx` の `Mobile320*` と `Mobile390*`。5 つの画面を 320px と 390px で出し、横スクロールがないこと、axe の違反がないこと、主な操作が 44px 以上であることを確かめる | PR の必須チェック        |
| E2E   | ログインからログアウトまでの 1 本を、Chromium、390px の viewport で。端末のエミュレーションはしない。[ADR 0039](../adr/0039-e2e-playwright-gate-and-ai-for-authoring.md) に従う            | merge 後と定期の実行だけ |
| 手動  | 下の「リリース前の実機の確認」                                                                                                                                                             | リリース前               |

E2E の基盤 (web のログインの E2E) は [Issue #453](https://github.com/yokozi-jp/agent-software-factory/issues/453) で作る。スマホの 1 本は、その後に足す。

## リリース前の実機の確認

iPhone と Android を各 1 台使い、縦持ちで次を確かめる。

1. ログイン画面で、ボタンが指で押せ、横スクロールが出ない。
2. ログインして、トップを開く。
3. 上部のボタンでメニューを開き、項目を選んで閉じる。
4. ユーザーメニューで、テーマの 3 択を切り替え、ログアウトする。
5. 存在しない URL と、権限のない URL を開き、403/404 の画面が崩れない。
