# はじめての非機能要件の出典と適用範囲

`docs/non-functional-requirements/` の文書は、フューチャー株式会社の [はじめての非機能要件](https://future-architect.github.io/arch-guidelines/documents/forNFR/) を元にしている。
非機能要件を定義し、関係者と合意するまでの進め方と、領域ごとの決め方を対象にする。

## 位置づけ

原文のトップページ「はじめに」から、規約として意味のある内容を原文のまま残す。

非機能要件はアーキテクチャを大きく左右するため、抜け落ちや認識齟齬があると大きな手戻りが発生する。そのため、できる限り早期に関係者と合意すべきである。しかし現状、要件定義から合意に至るプロセスは個人の経験に依存しがちで、標準的な手法が確立されていない。本ガイドラインでは、この様な状況を改善するため、非機能要件について円滑に合意形成するための手法をまとめる。

### 想定読者

本ガイドラインは、非機能要件の定義と合意をリードする立場の担当者を主な対象とする。「はじめての」と題しているが、まったくの初学者向けの入門書ではない。ここでの「はじめて」は非機能要件定義に取り組むのが初めてという意味であり、具体的には次のいずれかに当てはまる人を想定する（いずれも、個別技術の深い知識は前提としない）。

- プロジェクトのライフサイクルを一通り経験し技術的な勘所はついているが、非機能要件定義を担当するのは初めての人
- 非機能要件定義を経験頼み・我流で進めてきたが、標準的な型を身につけたい人

### 本書の構造

本ガイドラインは、最初からすべてを通読する必要はない。読者が直面している課題やプロジェクトのフェーズに合わせて、必要なノウハウへ最短でアクセスできるよう、役割の異なる3部構成とした。

- 第一部（全体プロセス編）: 非機能要件を定義し合意するまでの、ドメインに依存しない進め方と思考の型。初めての方はまず通読を推奨する。
- 第二部（個別ドメイン・ナレッジ編）: 可用性・性能など、要件ごとの具体的な決め方。必要な項目を辞書的に活用する。
- Appendix: 業界標準フレームワークや用語の正確な定義。裏取りの補助資料として用いる。

## 適用範囲と前提条件

本ガイドラインが暗黙的に想定するシステム像は、次の通りである。

- **主な対象**: Web アプリケーション（業務システム / Web サービス等）
- **インフラ形態**: クラウド・オンプレミスのいずれも対象とする
- **主な対象外**: 組み込み・IoT 機器、リアルタイム制御システムなど、Web アプリケーションとは非機能の関心事が大きく異なるシステム（電力制約・時間的確実性・物理制御など）
