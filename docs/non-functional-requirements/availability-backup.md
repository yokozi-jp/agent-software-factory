# 可用性のためのバックアップとデータ保全

データ保全は、可用性 (使い続けられるか) とは別の耐久性を支える土台であり、どのシステムでも必ず詰める。
可用性の要件としては、許容するデータ損失 (RPO) とデータ保全の範囲 (別リージョン・別拠点への退避の要否) を決める。
出典は [可用性](about.md) (CC BY 4.0) で、OKF の形式に合わせて分割、変更している。

## バックアップとデータ保全

どのシステムでも、データが失われないための備えは必要である。可用性（使い続けられるか）とは別に、耐久性（データが失われないか）を支える土台であり、ミッションクリティカルかどうかに関わらず必ず詰める（→「可用性と耐久性の混同に注意する」）。

可用性の要件として決めるのは、次の水準・範囲である。

| 項目                      | 内容                                                                                                 |
| :------------------------ | :--------------------------------------------------------------------------------------------------- |
| 許容するデータ損失（RPO） | 障害時にどの時点まで戻せればよいか（継続性の要素。→[可用性とは](availability-basics.md#可用性とは)） |
| データ保全の範囲          | リージョンや拠点の全損のような大規模障害に備え、別リージョンや別拠点へバックアップするかどうか       |

一方、バックアップの取得頻度・世代管理・ジョブ監視・リストア訓練といった運用は運用保守性で、取得方式や保管先といった構成は設計で扱う。バックアップからのリストアでは間に合わないほど短い RTO や、無停止での切り替え（スタンバイサイト、マルチリージョン稼働）が要る場合は、[高可用性要件](high-availability-uptime.md#高可用性要件)の[災害対策（DR・BCP）](high-availability-dr.md#災害対策と事業継続)で扱う。
