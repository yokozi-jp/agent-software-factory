# ドキュメント

- [開発環境の構築](local-env-setup/index.md)：開発に参加するとき、マシンを作り直したとき
- [開発ツール](tooling/index.md)：コマンドを探すとき、Git hook、CI、secret scan で止まったとき、それらを変えるとき
- [リポジトリ運用](repository/index.md)：コミットや PR を書くとき、リリースするとき、GitHub の設定を変えるとき
- [Architecture Decision Records](adr/index.md)：ツールや構成を追加、変更する前に既存の決定を確かめるとき、ADR を書くとき
- [ナレッジ管理](knowledge/index.md)：docs、steering、AGENTS.md を追加、変更するとき、知識をどこに書くか迷ったとき
- [エージェント設定](agents/index.md)：Issue tracker、triage ラベル、ドメイン文書の配置を確かめるとき、Matt Pocock の skill を使うとき、タスクの区切りで振り返るとき、工場の成果の指標を記録、集計するとき
- [ログ設計](logging/index.md)：アプリケーションのログを設計、実装、レビューするとき、ログ基盤の設定や費用を見直すとき
- [I/F設計](interface/index.md)：システム間のデータ連携（ファイル連携、Web API、メッセージングなど）を設計、実装、レビューするとき
- [メール設計と SMS](mail/index.md)：メールや SMS の送信を設計、実装するとき、到達性・レピュテーション・コンプライアンスを設計するとき
- [データガバナンス設計](data-governance/index.md)：データをビジネス資産として活用するための全社的なルールや体制を設計するとき、データ分類・メタデータ・品質・AI利活用の方針を決めるとき
- [Web API設計](web-api/index.md)：RESTライクな Web API のサーバーサイドを設計、実装、レビューするとき
- [はじめての非機能要件](non-functional-requirements/index.md)：非機能要件を定義し関係者と合意するとき、可用性などの要件ごとの決め方を調べるとき
- [ソフトスキル](soft-skills/index.md)：アーキテクトのソフトスキルを定義、評価、育成するとき、各スキルの観点を確かめるとき
- [Slack 利用](slack/index.md)：Slack でのコミュニケーションの進め方を決めるとき、投稿やメンション、通知の運用に迷うとき
- [帳票設計](report/index.md)：帳票を新規に作るか判断するとき、電子帳票や紙帳票を設計するとき
- [コードレビュー](code-review/index.md)：コードレビューの進め方を決めるとき、レビュアーやレビュイーの振る舞いを確かめるとき
- [アーキテクチャ原理原則と心得](architecture-principles/index.md)：アーキテクチャを設計するとき、技術選定や共通基盤化を判断するとき、設計の原則やマインドセットに立ち返りたいとき
- [バッチ設計](batch/index.md)：バッチ処理を設計・実装するとき、ワークフロー、業務日付、排他制御、パラメータ、テスト、リリースの方針を確かめるとき
- [非同期設計](async/index.md)：ある処理を非同期にすべきか判断するとき、キュー・順序保証・冪等性・DLQ など非同期処理の設計論点を調べるとき
- [Webフロントエンド設計](web-frontend/index.md)：Web フロントエンドの構成、動作、表示制御、認証認可、開発、テストを設計、実装、レビューするとき
- [テクニカルライティング](technical-writing/index.md)：文章やチャット、設計書、提案資料を書くとき、文章をレビュー・フィードバックするとき
- [DB設計](db/index.md)：PostgreSQL や DynamoDB のテーブル・インデックス・制約を設計するとき、データモデリング、排他制御、監視、BCP/DR などの DB 設計方針を確かめるとき
- [はじめての性能テスト](performance-test/index.md)：性能テストを計画・準備・実行・チューニング・レポーティングするとき
- [Markdown設計ドキュメント規約](markdown-design-docs/index.md)：アプリの設計書 (画面、テーブル、Web API、I/F など) を Markdown で書くとき。この docs/ の文書の書き方はナレッジ管理を読む
