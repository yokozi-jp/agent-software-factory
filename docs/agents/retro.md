# タスクの区切りでの振り返り

タスクの区切りで、エージェントは利用者に頼まれなくても `retro` skill を実行し、このセッションから環境の改善候補を出します。
反映するのは、利用者が選んだ候補だけです。
この規則を置いた理由は [ADR 0015](../adr/0015-retro-at-task-boundary.md) にあります。

## タスクの区切り

次のどれかに当たったときが、タスクの区切りです。

- PR を作り、CI の結果が出た後
- PR を作らずに Issue を閉じる前 (調査の結果を Issue に書いて閉じるときなど)
- 利用者が Issue を挙げずに頼んだ作業で、変更を commit し終えて完了を報告する前

1 つのタスクで実行するのは、最後の区切りの 1 回です。commit、push、レビューの指摘への対応は区切りではありません。
質問に答えるだけで、リポジトリも Issue も変えなかったやり取りは、タスクに数えません。
タスクの途中で利用者に別のタスクを頼まれたら、頼まれたタスクを先に進め、その区切りで両方のタスクをまとめて振り返ります。

## 実行の仕方

1. `retro` skill を読み込みます。Kiro では skill として読み込めます。skill として読み込めない実行環境 (Claude Code、Codex) では、`.agents/skills/retro/SKILL.md` を読んで、その手順に従います。
2. skill の手順のとおり、今のセッションを対象に改善候補を重い順に示し、どれを反映するかを利用者に聞いて止まります。
3. 利用者が選んだ候補だけを反映します。反映は元のタスクとは別のブランチと PR で行い、PR のタイトルで振り返りから直したことが分かるようにします (例: `docs: 振り返りから、…`。type は変更に合わせる)。

利用者が振り返りを断ったら、そのタスクではもう実行しません。

## 反映先の選び方

上から順に検討し、最初に当てはまるものにします。

1. **構造で誤りを書けなくする**: 型、モジュールの境界、雛形、ファイルの置き場所を変えて、誤った書き方そのものができないようにします。誤りが書けなくなれば、検査も docs も要りません。
2. **検査にする**: 機械的に判定できる誤り (決まった書き方、禁止の API、import の形、ファイルの置き場所の規則) は、lint の規則、`scripts/` の検査、Git hook、Kiro の hook、CI のどれかで止めます。
3. **docs に書く**: 判断が要るものだけを書きます。レビューで見る規約は `CODING_STANDARDS.md`、手順や規約は `docs/` の該当する領域に書き、`AGENTS.md` にはポインタだけを足します ([AGENTS.md、steering、docs、IWE の役割分担](../knowledge/knowledge-architecture.md))。

upstream から入れた skill (`.agents/skills/**`) は、`skills-lock.json` と一致させたまま変えません。skill の手順を直したい候補は、この文書か、upstream への提案にします。
